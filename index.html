The program

/* rows[1] to rows[40] hold the rows */
const char *lookup(const char *input) {
    if (strlen(input) != 4)
        return "invalid input";
    if (input[0] != 'A' || input[1] != '7')
        return "invalid input";
    if (input[2] < '0' || input[2] > '9' ||
        input[3] < '0' || input[3] > '9')
        return "invalid input";
    int n = (input[2] - '0') * 10
          + (input[3] - '0');
    if (n > 40)
        return "out of range";
    return rows[n]->text;
}

The techniques

The technique

Symbolic execution

Tool KLEE

Leave the input open and follow every path at once.

Coverage-guided fuzzing

Tool AFL++

Change inputs at random and keep the ones that reach new lines.

Concolic execution

Tool SymCC

Run a seed, then go back and flip one branch at a time.

Hybrid fuzzing

Tool AFL++ with SymCC

The fuzzer explores and a solver writes inputs that pass the checks.

Bounded model checking

Tool CBMC

Cover every input with one formula, then ask the solver.

Property-based testing

Tool theft

Write a rule and a generator, then look for a counterexample.

Which way is best?

This example is simple enough to fit on a page, so they can all get there. Agolic is built for real programs, large ones included, where no technique today wins every time. Each one trades a strength for another and our paper measures some of those trade-offs. Maybe you will build the tool that beats them all.
